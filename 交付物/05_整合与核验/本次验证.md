## 3. 怎么复现

```bat
REM 1) 用临时数据库启动被测服务（新开一个窗口，保持运行）
set AI4EN_DB_PATH=%CD%\.tmp\verify.db
python app\server.py --port 8851

REM 2) 另开一个窗口，指向该服务跑两套检查
set AI4EN_BASE=http://127.0.0.1:8851
python tests\smoke_test.py
python tests\acceptance.py http://127.0.0.1:8851
```

`smoke_test.py` 不带 `AI4EN_BASE` 时会自己拉起服务；带该变量时只连已有服务，便于在受限环境复现。
`acceptance.py` 只连已有服务，第二条参数可换地址。

## 5. 基线回归 45 项与本轮修复

`tests/smoke_test.py` 覆盖原项目的发布、提交、权限、导出、打印、日志、错题组卷与生成失败。本次运行先得到 **40 / 45**，逐项定位后修复，再运行得到 **45 / 45**：

| 未通过项 | 原因 | 处理 |
| --- | --- | --- |
| 退出登录撤销服务器会话（重放旧 Cookie 仍返回 200） | `api.dispatch` 没有把会话 token 放进上下文，`api_logout` 拿到 `None`，服务器会话从未删除 | `dispatch(..., token)` 透传 token，退出即删除会话；重放旧 Cookie 返回 401 |
| POST 访问静态页返回 200 | 静态处理不区分方法 | 静态资源只接受 GET，其余返回 405 |
| 学生同时看到“句架”和“关键词” | 学生接口只剥离答案，没有按本次选用的支架过滤 | 新增 `student_items()`：按任务 `support` 只保留一种支架；关闭提示时连 `hint` 一并移除 |
| 错题组卷发布后变成整份 7 题 | 发布时无条件用课例练习覆盖任务快照 | 快照标记 `origin=review`，发布与复制都保留所选题目 |
| 错题组卷用例在“答案缺失”用例之后连带失败 | 用例把第 1 题答案清空后没有恢复，后续发布被 400 拦截 | 负向用例结束后恢复答案并重新审核，属于用例缺陷，已修正 |

前四项是代码缺陷，都已修复并用同一脚本回归；第五项是用例自身的状态污染，修的是测试而不是应用。

## 7. 没有验证的部分

- **真实模型调用**：没有配置 `AI4EN_LLM_*` / `DEEPSEEK_API_KEY`，所有生成内容均为“示例内容”，数字人走脚本对话；只验证了“调用失败时保留草稿、写日志、可重试”和“未配置时明确返回 503”的路径。
- **真实课堂**：演示数据是 1 个班 6 名虚拟学生，没有真实教师/学生长期使用数据，不对学习效果作结论。
- **外部工具**：工作坊与完整版里的外部 AI 工具只提供入口与提示词，不验证其账号、额度与可用性。
- **完整版页面交互**：只做了静态入口与接口层检查；游戏、麦克风录音、思维导图拖拽需要现场用浏览器操作。
